# ТЗ.md — техническое задание на сайт Minecraft-сервера

## 1. Назначение проекта

Нужно создать сайт для Minecraft-сервера `NATUX WORLD` с донат-магазином.

Зафиксированные данные проекта:

- основной домен: `natuxworld.ru`;
- Minecraft IP: `mc.natuxworld.ru`;
- VK: `https://vk.com/natuxworld`;
- логотип: `public/logo.svg`.

Сайт должен позволять игроку:

- посмотреть информацию о сервере;
- узнать IP и версию;
- выбрать донат-ранг;
- выбрать срок действия привилегии;
- ввести Minecraft-ник;
- оплатить заказ;
- автоматически получить донат на сервере;
- проверить статус заказа.

Администратор должен иметь возможность управлять товарами, заказами, выдачей и настройками магазина.

---

## 2. Главные требования

- сайт в тёмной красно-чёрной стилистике;
- адаптивная верстка для ПК и телефонов;
- магазин доната как основной раздел;
- оплата через выбранную платежную систему;
- автоматическая выдача доната после оплаты;
- защита от двойной выдачи;
- админ-панель;
- логирование заказов, оплат и выдач;
- безопасное хранение секретов;
- возможность менять ранги, цены и команды выдачи без изменения кода.

## 4. Пользовательский сценарий покупки

1. Игрок открывает магазин.
2. Выбирает донат-ранг.
3. Выбирает срок действия.
4. Вводит Minecraft-ник.
5. Сайт валидирует ник.
6. Игрок нажимает `Купить`.
7. Backend создаёт заказ.
8. Backend создаёт платёж в платежной системе.
9. Игрок переходит на страницу оплаты.
10. После оплаты платежная система отправляет webhook.
11. Backend проверяет webhook.
12. Заказ получает статус `paid`.
13. Создаётся задача на выдачу доната.
14. Backend отправляет команду на Minecraft-сервер через RCON.
15. Заказ получает статус `delivered`.
16. Игрок видит успешный статус.

## 5. Валидация Minecraft-ника

Для Java-ника:

- длина от 3 до 16 символов;
- разрешены латинские буквы;
- разрешены цифры;
- разрешён символ `_`;
- пробелы запрещены;
- спецсимволы запрещены.

Если сервер поддерживает Bedrock/Geyser, правила ника нужно будет дополнить.

---

## 6. Оплата

### 6.1. Общая логика

- Цена берётся только из базы данных на backend.
- Frontend не может передавать свою цену.
- Заказ создаётся до перехода к оплате.
- Донат выдаётся только после успешного webhook.
- Возврат пользователя на сайт не считается подтверждением оплаты.

### 6.2. Платежная система

Платежная система выбирается отдельно.

Возможные варианты:

- YooKassa;
- Robokassa;
- FreeKassa;
- CloudPayments;
- Lava;
- Enot;
- UnitPay.

### 6.3. Webhook

При получении webhook backend должен:

- проверить подпись;
- проверить ID платежа;
- проверить сумму;
- проверить валюту;
- найти заказ;
- убедиться, что заказ ещё не был выдан;
- изменить статус оплаты;
- создать задачу выдачи;
- сохранить payload webhook в лог.

## 8. Автоматическая выдача доната

### 8.1. Первый вариант реализации

Для первого релиза использовать RCON.

Backend после оплаты подключается к Minecraft-серверу и выполняет команды выдачи.

### 8.2. Пример команд LuckPerms

Для временного ранга:

- `lp user {username} parent addtemp {rank} 30d accumulate`
- `lp user {username} parent addtemp {rank} 90d accumulate`

Для вечного ранга:

- `lp user {username} parent add {rank}`

### 8.3. Переменные в командах

Команды должны поддерживать переменные:

| Переменная | Значение |
|---|---|
| `{username}` | Minecraft-ник |
| `{rank}` | техническое имя ранга |
| `{duration}` | срок текстом |
| `{duration_days}` | срок в днях |
| `{order_id}` | ID заказа |
| `{price}` | сумма заказа |

### 8.4. Несколько команд на один товар

Один товар может выполнять несколько команд.

Например:

- выдать группу;
- выдать игровую валюту;
- выдать ключи;
- отправить broadcast;
- отправить личное сообщение игроку.

---

## 9. Защита от двойной выдачи

Обязательные требования:

- один заказ не может быть выдан дважды;
- повторный webhook не должен повторно запускать команды;
- у заказа должен быть отдельный статус выдачи;
- каждая команда должна логироваться;
- перед выдачей backend проверяет, не был ли заказ уже выдан;
- при ошибке выдачи создаётся запись для повтора.

---

## 10. Ошибки выдачи

Если Minecraft-сервер недоступен или RCON не отвечает:

- заказ не удаляется;
- заказ получает статус `delivery_failed`;
- ошибка сохраняется в лог;
- админ получает уведомление;
- админ может повторить выдачу вручную.

Рекомендуемые попытки:

1. сразу после оплаты;
2. через 1 минуту;
3. через 5 минут;
4. через 15 минут;
5. дальше вручную через админку.

## 11. Админ-панель

### 11.1. Авторизация

Админ-панель должна быть закрыта авторизацией.

- защита от перебора;

- logout;

### 11.2. Управление заказами

Админ видит:

- ID заказа;
- дату;
- ник;
- товар;
- срок;
- сумму;
- статус оплаты;
- статус выдачи;
- ошибку, если она есть.

Действия:

- открыть заказ;
- повторить выдачу;
- отметить как выданный вручную;
- отменить заказ;
- посмотреть webhook;
- посмотреть RCON-логи.

### 11.3. Управление товарами

Админ может:

- создавать ранги;
- менять название;
- менять описание;
- менять цены;
- менять сроки;
- менять команды выдачи;
- включать/выключать товар;
- менять порядок отображения.

### 11.4. Промокоды

Промокоды должны поддерживать:

- процентную скидку;
- фиксированную скидку;
- лимит использований;
- срок действия;
- включение/выключение;
- привязку к товарам.
