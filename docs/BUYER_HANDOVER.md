# NATUX WORLD Launcher — передача проекта

Этот документ нужен новому владельцу лаунчера. Он описывает фактическое
состояние проекта, границы ответственности и безопасный порядок передачи.

## Что входит в репозиторий

- Electron-лаунчер для Windows и macOS на React + TypeScript.
- Установка Java, Minecraft и Forge 1.21.1; запуск с быстрым подключением к серверу.
- Регистрация, вход, подтверждение e-mail и игровая offline-идентичность через API второго репозитория.
- Настройки игры, логи запуска и отчёты о падениях.
- Windows-автообновление: перед скачиванием проверяются Ed25519-подпись манифеста,
  версия, имя установщика и SHA-512 файла.
- GitHub Actions: тесты, сборки Windows/macOS и публикация релизов по версии в `package.json`.

## Связь со вторым репозиторием

Лаунчер работает вместе с [minecraft-server](https://github.com/Alex-dev-sys/minecraft-server):

| Часть | Роль |
|---|---|
| Этот репозиторий | Клиент игрока: установка, запуск Minecraft, UI, обновления |
| `minecraft-server` | Сайт, аккаунты, e-mail, Yggdrasil authserver, магазин, PostgreSQL, RCON и админ-панель |

Для полной передачи покупателю нужны оба репозитория и доступы к их инфраструктуре.

## Быстрый старт для разработчика

```bash
npm ci
npm run lint
npm run typecheck
npm test
npm run dev
```

Для production-сборки используются GitHub Actions. PR в `main` только проверяет
сборку; push новой версии в `main` публикует релиз автоматически.

## Передача доступов

Передавай через защищённый менеджер паролей, а не в Git или чат:

1. Права владельца обоих GitHub-репозиториев и GitHub Actions.
2. Секрет `UPDATE_SIGNING_PRIVATE_KEY` из GitHub Actions.
3. Доступ к домену/DNS, хостингу сайта, PostgreSQL, почте и платёжным кабинетам.
4. Доступ к Minecraft-серверу, RCON и настройке authlib-injector, если они используются.
5. Аккаунты Vercel/VPS и резервные копии БД.

> Важно: закрытый ключ обновлений нельзя извлечь из GitHub Secret после сохранения.
> До передачи владелец должен создать и проверить резервную копию ключа. Если ключ утрачен,
> потребуется отдельный релиз с новой парой ключей для Windows-обновлений.

## Проверка перед продажей

- [ ] `npm run lint`, `npm run typecheck`, `npm test` проходят.
- [ ] Последний GitHub Release содержит Windows Setup, Portable, macOS `.dmg`,
  `latest.yml`, `natux-update.json`, `natux-update.json.sig` и checksums.
- [ ] Обновление с предыдущей Windows-версии на тестовую версию установлено успешно.
- [ ] API второго репозитория доступен по HTTPS; регистрация, вход и запуск игры проверены.
- [ ] Новый владелец получил доступы из раздела выше и сменил чувствительные секреты.

## Что требует решения новым владельцем

- В коде сейчас есть брендовые адреса `vibestudy.ru` и `mc.vibestudy.ru`.
  При ребрендинге их нужно заменить или вынести в единый build-конфиг до выпуска
  лаунчера под новым доменом.
- macOS `.dmg` не notarized: Gatekeeper покажет предупреждение. Для коммерческого
  распространения нужен Apple Developer ID, подпись и notarization.
- Windows-инсталлятор не имеет Authenticode-сертификата. Ed25519 защищает канал
  обновления, но не убирает предупреждение SmartScreen.

## Как выпустить обновление

1. Внести изменение и прогнать локальные проверки.
2. Изменить версию: `npm version <version> --no-git-tag-version`.
3. Создать PR в `main`; CI должен пройти без публикации.
4. Влить PR. GitHub Actions выпустит версию, подпишет update-манифест и создаст тег.
5. Проверить обновление с предыдущей установленной Windows-версии.

## Материалы для объявления о продаже

Перед публикацией объявления сделай свежие скриншоты: экран входа, главный экран,
настройки, процесс обновления, магазин и админ-панель из второго репозитория.
Не публикуй секреты, IP админки, RCON-данные, пользовательские e-mail или реальные
платёжные заказы.
