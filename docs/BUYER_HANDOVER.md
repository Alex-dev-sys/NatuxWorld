# NATUX WORLD Server Platform — передача проекта

Этот документ описывает фактический состав серверной платформы для нового
владельца. Он не заменяет настройку домена, платежей и Minecraft-хоста.

## Что входит в репозиторий

- Сайт и магазин на Next.js + TypeScript.
- PostgreSQL + Prisma и миграции схемы.
- Регистрация, подтверждение e-mail, 2FA, app-passwords и JWT-сессии.
- Yggdrasil authserver/sessionserver для связки с лаунчером.
- Заказы, промокоды, YooKassa, CryptoBot, YooMoney и mock-режим разработки.
- Идемпотентная выдача привилегий через RCON и админ-панель.
- Paper-плагин для игровых событий и интеграции с API.
- Docker Compose, Nginx, health-check БД и сценарий резервного копирования PostgreSQL.

## Связь с лаунчером

Второй репозиторий — [NatuxWorld](https://github.com/Alex-dev-sys/NatuxWorld).
Он использует этот сайт для аккаунтов, crash reports и Yggdrasil. При передаче
одного продукта покупатель должен получить оба репозитория.

## Быстрый запуск в разработке

```bash
cp .env.example .env
# Заполни DATABASE_URL для тестовой PostgreSQL
npm ci
npx prisma migrate deploy
npm run dev
```

Проверки проекта:

```bash
npm run lint
npm run typecheck
npm test
npm run build
```

## Production на VPS

Подробные команды находятся в [DEPLOY.md](../DEPLOY.md). В кратком виде:

```bash
cp .env.example .env
# заполнить реальные секреты и домен
docker compose up -d --build
curl -fsS https://<ваш-домен>/api/health
./scripts/backup-postgres.sh
```

Эндпоинт `/api/health` вернёт `200` только когда приложение может выполнить
запрос к PostgreSQL. Скрипт backup создаёт сжатый дамп и удаляет локальные
копии старше 14 дней; дамп нужно дополнительно отправлять в отдельное хранилище.

## Передача доступов

Передавай через менеджер паролей. В Git не должны попадать `.env`, ключи и дампы:

1. GitHub, Vercel и/или VPS; DNS и SSL-сертификаты.
2. PostgreSQL и проверенный внешний backup.
3. SMTP, платёжные кабинеты и webhook-секреты.
4. RCON, API-ключ Paper-плагина, SSH bridge (если включён).
5. `JWT_SECRET`, `ADMIN_SECRET`, `ADMIN_TOTP_SECRET`, `TWOFA_ENC_KEY` и
   `YGGDRASIL_PRIVATE_KEY`.

После передачи сменить все секреты и проверить платежи только в test/mock-режиме
до включения боевых webhook.

## Проверка перед продажей

- [ ] CI проходит: миграции, тесты, Next build и Paper plugin.
- [ ] Для нового домена согласован один источник правды: `.env`, Nginx и настройки лаунчера.
- [ ] PostgreSQL доступна, `/api/health` возвращает `200`.
- [ ] Создан backup и выполнено тестовое восстановление в отдельную БД.
- [ ] RCON выдаёт тестовую привилегию на тестовом пользователе.
- [ ] Реальные webhook проверены тестовым платежом либо отключены до настройки владельцем.
- [ ] В админ-панели включены сильный пароль, TOTP и IP allowlist.

## Что требует решения новым владельцем

- В старых документах и части конфигов встречаются `vibestudy.ru` и `natuxworld.ru`.
  До production нужно выбрать фактический домен и привести `.env`, `nginx.conf`,
  DNS, SSL и адреса в лаунчере к одному значению.
- Значения `mock` в `.env.example` предназначены для разработки, не для реальных платежей.
- RCON и SSH bridge дают доступ к Minecraft-хосту; держи их только во внутренней сети
  и не публикуй порты в интернет без необходимости.
