## 🟡 Средние

### Main-процесс

- `ipc/handlers.ts:46` — `settings:verifyJava` спавнит **любой** путь от рендерера + нет таймаута (висящий бинарь = вечный pending). Фикс: basename ∈ {java, javaw}(.exe), kill-таймаут.
- `ipc/handlers.ts:21-64` — ноль валидации входа на всех IPC-хендлерах; `opts.memory` течёт в `-Xmx${memory}M` без проверки (NaN/мусор = битый JVM-флаг). Фикс: клампить числа, валидировать строки.
- `DownloadService.ts:90` — частичные `.tmp`-файлы не чистятся при generic stream-ошибке (только при sha/size mismatch). Фикс: unlink tmp перед каждой попыткой.
- `main.ts:83` — `setInterval(updater.check, 30min)` не очищается, promise без `.catch`. Фикс: хранить id, чистить на quit.
- `LauncherService.ts:113,373` + `UpdateService.ts:89` — `webContents.send` на уничтоженном окне кидает. Фикс: guard `!window.isDestroyed()`.
- `MojangService.ts:134` — кэш version-json не проверяется по sha1 (битый кэш → битый запуск). Фикс: сверять sha1 из манифеста.
- `ForgeService.ts:203` — Forge-инсталлер проверяется только «открывается как zip», потом исполняется. MITM = выполнение кода. Фикс: пиннить sha1 инсталлера.
- `JavaService.ts:184` — redirect-ответы не дренятся (`res.resume()`), ошибки промежуточных ответов без хендлера.

## ✅ Что сделано хорошо (не ломать)

- **Целостность загрузок**: sha1/sha256 + атомарный `.tmp`→rename + ловля обрывов по size mismatch (DownloadService, JavaService).
- **Zip-extraction** защищён от zip-slip (`..`, абсолютные пути, null-байты, backslash).
- **Базовая безопасность Electron**: `contextIsolation: true`, `nodeIntegration: false`, типизированный contextBridge без сырого ipcRenderer.
- **Forge-кэш** валидируется по json+client-jar (фикс 4434118) — продуманный guard.
- 10 из 12 main-сервисов покрыты тестами; strict TS в обоих tsconfig; typecheck-гейт в CI.
- Чистые cleanup'ы листенеров в хуках; `AccountResult` как discriminated union вместо throw; AuthGate-стейт-машина проста и корректна.
